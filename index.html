Google DeepMind

Gemini

장점

설계 초기부터 텍스트·비디오·오디오를 동시에 처리하는 네이티브 멀티모달 구조. 문맥 기억 용량이 100만~200만 토큰 이상으로 업계 최대 수준이며, 구글 검색과 결합해 사실성 검증 능력이 뛰어납니다.

단점

안전성 필터가 엄격해 보안 테스트나 역사적 질의에서도 답변을 거부하는 경우가 있습니다. 복잡하게 중첩된 지시에서 세부 조건을 누락할 수 있습니다.

OpenAI

ChatGPT (GPT 계열)

장점

연쇄 추론과 강화학습을 통해 기호 수학·과학 논리·코드 디버깅에서 스스로 오류를 점검합니다. 구조화된 JSON 출력, 파이썬 실행기 등 외부 도구 연동과 개발자 API 생태계가 가장 성숙합니다.

단점

깊은 추론 작업은 생성 전 생각하는 시간이 길고 토큰 소모와 비용이 큽니다. 긴 문서에서 중간 부분의 세부 정보를 놓치는 현상이 상대적으로 관찰됩니다.

Anthropic

Claude (클로드 계열)

장점

실제 깃허브 버그를 해결하는 SWE-bench에서 최상위 성능을 보입니다. 모르는 정보를 지어내지 않고 한계를 명확히 짚는 환각 방지 조율이 엄격하며, 자연스러운 문장 작성 능력이 뛰어납니다.

단점

입력 문맥 창이 통상 20만 토큰 수준으로 제미나이의 초대용량 처리에 비해 물리적 한계가 있습니다. 실시간 비디오·음성 네이티브 처리도 텍스트·이미지 대비 제약이 있습니다.

xAI

Grok (그록 계열)

장점

X(구 트위터)의 실시간 소셜 데이터와 직접 연동되어 웹 인덱싱 전 초단위 글로벌 속보와 최신 반응 파악에 유리합니다. 응답 속도가 빠르고 민감한 주제도 회피하지 않고 직설적으로 다룹니다.

단점

미검증 루머나 정제되지 않은 데이터가 반영되어 사실성 검증·출처 정확도에서 오류율이 높습니다. 기업용 보안 통제와 조직 관리 기능 등 비즈니스 API 인프라가 상대적으로 부족합니다.

웹으로는 안 되는 일 → 배치 파일로

사용자 PC 안에서 자동화해야 하는 작업은 웹 상태로는 수행할 수 없습니다. 이때 LLM에게 "내 PC에서 실행 가능한 배치 파일 코드를 작성해줘"라고 요청합니다.

  1. 01_project_init.bat프로젝트 표준 폴더 구조와 README·index.html 기본 파일 자동 생성
  2. 02_auto_organize.bat흩어진 파일을 확장자별로 사진·문서·압축파일·실행파일 폴더로 자동 분류
  3. 03_auto_backup.bat타임스탬프(YYYYMMDD_HHMMSS)가 붙은 폴더로 자동 백업
  4. 04_batch_rename.bat이미지 파일에 접두사와 일련번호(001, 002…)를 붙여 일괄 이름 변경
  5. 05_dev_startup.bat자주 쓰는 웹사이트·메모장·터미널을 한 번에 실행
  6. 06_temp_cleaner.bat사용자 Temp와 시스템 Temp 폴더의 임시 파일 정리
  7. 엑셀 10개 자동 생성파워셸을 호출해 양식이 포함된 엑셀 파일 10개를 한 번에 생성

반복 실행이 필요하면 하루 한 번은 작업 스케줄러, 짧은 주기 반복은 배치 파일 안의 timeout 루프 또는 스케줄러의 반복 간격 설정을 사용합니다.

05 SESSION 05 · 에이전트 실습 (1) Agent 실습 (1) — Opencode 설치와 로컬 기능 내 PC의 파일·터미널을 직접 다루는 에이전트를 설치하고 기본 기능을 익힙니다.

실습 흐름

  1. 설치Opencode를 설치하고 터미널에서 실행합니다.
  2. 권한 확인읽기 전용 / 자동 실행 / 전체 자율 등 허용 범위를 먼저 설정합니다.
  3. 로컬 기능 실습프로젝트 폴더 읽기, 파일 수정, 터미널 명령 실행, 테스트까지 요청합니다.
  4. 결과 확인에이전트가 바꾼 파일과 명령어 로그를 직접 검토합니다.
로컬 에이전트의 특징

내 컴퓨터의 코드 폴더를 직접 읽고 파일을 수정하며 터미널 명령을 실행합니다. 내 PC가 켜져 있을 때 동작하고, 노트북을 닫으면 실행이 멈춥니다. 개발이나 로컬 파일 보안이 중요한 작업에 적합합니다.

06 SESSION 06 · 에이전트 실습 (2) Agent 실습 (2) — 웹(앱)사이트 제작 + GitHub Opencode로 사이트를 만들고, GitHub 계정과 Repository까지 생성합니다.

실습 흐름

  1. 사이트 기획원하는 화면과 섹션을 글로 정의하고 에이전트에게 전달합니다.
  2. 제작Opencode로 HTML·CSS·JavaScript 파일을 생성하고 로컬에서 확인합니다.
  3. 수정 요청색감·문구·반응형 등 변경 사항을 대화로 반영합니다.
  4. GitHub계정 생성 → 새 Repository 생성 → 파일 업로드까지 진행합니다.
배운 개념 연결

4회에서 만든 배치 파일로 폴더 구조를 잡고, 5회에서 익힌 로컬 에이전트로 코드를 작성한 뒤, 6회에서 그 결과물을 GitHub에 올립니다.

07 SESSION 07 · 에이전트 실습 (3) Agent 실습 (3) — 다양한 모델로 웹(앱)사이트 제작 같은 목표를 여러 모델·에이전트에 맡겨 결과물과 작업 방식을 비교합니다.

비교 포인트

  • 같은 요청을 Claude Code, Codex CLI, Grok Build, Antigravity CLI에 각각 전달하기
  • 사전 계획(Plan Mode), 권한 승인 단계, 병렬 서브에이전트, 브라우저 확인 등 작업 방식의 차이 관찰하기
  • 완성된 화면의 completeness, 코드 구조, 수정 용이성 비교하기
  • 어떤 모델이 어떤 유형의 작업에 유리했는지 정리하기

1회에서 본 벤치마크 수치와 실제 체감 결과가 어떻게 다른지도 함께 돌아봅니다.

08 SESSION 08 · 마무리 총복습 1회~7회까지 배운 내용을 정리하고 수강생 질문에 답합니다.

복습 범위

1~2회4대 LLM 비교, 벤치마크, 프롬프트 15원칙
3~4회엑셀 분석, 파일 업로드 한계, 배치 자동화
5~6회Opencode 로컬 실습, 웹사이트 제작, GitHub 업로드
